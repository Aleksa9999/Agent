# 02: Роли, группа, темы и команды владельца

## Что построить

Новый участник тестовой группы получает тему со своим именем и кнопку «Начать с моим агентом». По кнопке открывается личка с темами «Профиль», «Навыки», «Проект», «Отчёты»; если клиент не поддерживает темы, работает `/project`. Роли определяются по Telegram-ID из серверного реестра. Команды владельца видны и доступны только ему. Повторные нажатия и старые кнопки не создают дублей.

## Критерии приёмки

- [x] Новый участник тестовой группы получает тему со своим именем и кнопку «Начать с моим агентом»; `/start` создаёт в личке темы «Профиль», «Навыки», «Проект», «Отчёты», а без поддержки тем работает `/project`. Весь путь в тесте занимает меньше 5 секунд (проверено на записанном Telegram, не на живом).
- [x] Команды руководителя работают только для Telegram-ID из `OWNER_TG_ID`; меню с этими командами выставляется только в чате владельца; все остальные получают отказ, роль не зависит от имени или username.
- [x] Повторное вступление, дубли апдейтов (`chat_member` и служебное сообщение) и одновременные события не создают вторую тему.
- [x] Старая, чужая или непонятная кнопка получает понятный ответ «Эта кнопка устарела», а не ошибку.

## Остаётся проверить на тестовом боте (ворота 1)

Тесты работают на записанном ответе Telegram, а не на живом. На живом тестовом боте нужно один раз проверить:
- бот добавлен в группу администратором с правами на темы, закрепление и удаление, режим приватности выключен, иначе событие `chat_member` не придёт;
- метод создания тем в личке работает у вашего клиента (при отказе включается `/project`);
- после `python -m app.bot.setup` Telegram доставляет апдейты на вебхук, ответ меньше 5 секунд.
