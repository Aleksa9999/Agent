## Назначение

Git и GitHub: установка, репозиторий, коммит, откат: методика из материалов студии (урок 02), превращённая в навык. Результат: настроенный Git и GitHub CLI.
Навык работает в одну фазу (`runs_via: direct`): агент проводит методику по тексту ниже, а при
необходимости оборачивается в полный конвейер `dev-skills` внутри более крупного навыка.

## Когда включать

- нужно сохранять версии проекта
- первый раз выкладываю проект на GitHub
- хочу откатиться к рабочей версии

## Допрос

Вопросы и порядок заданы методикой ниже. Общие правила студии для всех вопросов: пачками не больше пяти,
у каждого вопроса пронумерованные варианты или рекомендация, ответы, уже данные в паспорте или `_docs`, не
переспрашиваются, размытый ответ переспрашивается один раз с примерами.

## Конвейер

Одна фаза: провести методику строго по тексту. Текст методики ниже взят из материалов урока без изменений.
Если методика требует файла в `_docs/`, он создаётся только после подтверждения человека.

### Методика (текст урока)

```text
### Установка Git
Мне на систему нужно установить git, чтобы я мог из терминала с ним работать. Выполни установку и, если нужны от меня какие-то действия, запрашивай.
После установки выполни корректную настройку системы git, чтобы я мог дальше спокойно работать с репозиториями и пушить изменения.

### Доступ через GitHub CLI
Настрой мне работу с GitHub через GitHub CLI. Установи `gh`, если его ещё нет, и авторизуй меня по токену: [ТОКЕН].
После авторизации настрой git так, чтобы все операции с гитом работали без запроса пароля. Если для установки нужны действия с моей стороны — запрашивай.

### Создаём репозиторий
Мне нужно инициализировать гит в данном проекте и отправить проект на удаленный сервер в github. Вот ссылка: [ССЫЛКА].
В удалённой репозитории пока содержится только файл README.
Если возникнут какие-то проблемы с конфигурацией и нужны будут действия с моей стороны, то запрашивай, я их выполню.
В результате работы проект должен оказаться удаленно и я должен иметь возможность полноценно работать с гитом.

### Коммит
Сделай коммит с коротким описанием того, что поменялось.

### Отправка на GitHub
Отправь изменения на GitHub.

### Откат к предыдущему коммиту
Мне не нравится результат. Откати проект к предыдущему коммиту.

### Правило: коммить перед задачей
После того как я подтвердил, что фича работает, предлагай зафиксировать изменения коммитом с коротким описанием.
```

## Критерии приёмки

- **К1.** Git установлен и настроен: имя и email, push работает без запроса пароля.
- **К2.** Проект инициализирован и отправлен на GitHub в ветку `main`.
- **К3.** Коммит сделан с коротким описанием изменений.
- **К4.** Откат к предыдущему коммиту выполнен без потери истории.
- **К5.** В `CLAUDE.md` добавлено правило предлагать коммит после подтверждённой работающей фичи.
- **К6.** Токен нигде не записан: ни в логах, ни в файлах, ни в истории Git.

## Отказы и границы

- Токен GitHub человек вводит скрытым вводом в Mini App или в переменную окружения; в текст промпта и в чат токен не вставляется, в отличие от урока.
- Не делает `force push` и не стирает историю без явного согласия человека.
- Не обещает человеку заработок и не выдаёт гипотезу за факт.
- Факты о рынке, ценах и правилах берёт только из `run_research` со ссылкой и датой.
