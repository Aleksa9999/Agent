## Назначение

Стек проекта: методика из материалов студии (урок 02), превращённая в навык. Результат: `_docs/stack.md` в формате «Слой — Технология — Обоснование».
Навык работает в одну фазу (`runs_via: direct`): агент проводит методику по тексту ниже, а при
необходимости оборачивается в полный конвейер `dev-skills` внутри более крупного навыка.

## Когда включать

- выбрать технологии под проект
- перед инициализацией проекта
- нет `_docs/stack.md`

## Адаптация под паспорт

| Переменная | Что меняет |
|---|---|
| `{platform}` | веб, бот, Mini App, мобильное: меняет набор слоёв |
| `{country}` | хостинг, платежи и хранилище под страну |
| `{hosting}` | по методике: Dokploy и Yandex Object Storage; для самого проекта Googlagent решение Арсена — Timeweb и S3 Timeweb, это записывается в `_docs/stack.md` репозитория |

Адаптация меняет формулировки, примеры и порядок вопросов. Правила методики и критерии приёмки не ослабляются.

## Допрос

Вопросы и порядок заданы методикой ниже. Общие правила студии для всех вопросов: пачками не больше пяти,
у каждого вопроса пронумерованные варианты или рекомендация, ответы, уже данные в паспорте или `_docs`, не
переспрашиваются, размытый ответ переспрашивается один раз с примерами.

## Конвейер

Одна фаза: провести методику строго по тексту. Текст методики ниже взят из материалов урока без изменений.
Если методика требует файла в `_docs/`, он создаётся только после подтверждения человека.

### Методика (текст урока)

```text
### Стек проекта
Роль: ты — практикующий software-архитектор. Твоя задача — подобрать
стек технологий под мой проект и зафиксировать его в `_docs/stack.md`.
Делай строго по шагам ниже:
Изучи контекст
- Прочитай файлы в каталоге `_docs/` (`project.md`, `features.md`). Цель: понять продукт, ключевой функционал.
Задай мне уточняющие вопросы
- Если нужно, задай вопросы для того, чтобы составить наиболее корректный для продукта стек технологий.
Подбери стек и согласуй со мной содержимое `_docs/stack.md`
- На основе `_docs/` и моих ответов выбери технологии для создания продукта
- Нужно покрыть все слои, релевантные проекту. Минимальный список:
Frontend, Backend, База данных, Кэш, Файловое хранилище,
Авторизация, AI/LLM (если есть в продукте), Платежи (если есть),
Инфраструктура/Deploy, Мониторинг/Логирование.
- Если слой проекту не нужен — не включай его, не пиши «не требуется».
- Формат файла `_docs/stack.md` — ровно такой: Слой - Технология - Обоснования.
- Нужно составить файл максимально лаконично, без воды и ненужной информации, чтобы по нему было легко ориентироваться.
Важно: если продукт подразумевает веб приложение, то минимальный стек должен быть следующим: TypeScript, Next.js, React, Tailwind, Docker, Dokploy, Yandex Object Storage (S3), PostgreSQL, Prisma
```

## Коробка ИИ

| Уровень | Роли моделей |
|---|---|
| Эконом | `reasoning` |
| Стандарт | `reasoning`, `fast` |
| Премиум | `reasoning`, `fast`, проверка вторым проходом |

Цены считаются из `model_catalog`. Методика не требует дорогих генераций: уровни различаются глубиной проверки и поиска.

## Критерии приёмки

- **К1.** Файл лаконичный, в формате «Слой — Технология — Обоснование».
- **К2.** Покрыты все релевантные слои; ненужные слои не упомянуты.
- **К3.** Для веб-приложения минимальный стек включает TypeScript, Next.js, React, Tailwind, Docker, Dokploy, S3, PostgreSQL, Prisma.
- **К4.** Человек согласовал содержимое до записи файла.

## Отказы и границы

- Не пишет «не требуется» для лишних слоёв: их просто нет.
- Цены и версии берёт только из поиска со ссылкой.
- Не обещает человеку заработок и не выдаёт гипотезу за факт.
- Факты о рынке, ценах и правилах берёт только из `run_research` со ссылкой и датой.

## Доказательство «Сработало»

`_docs/stack.md` в репозитории; следующий шаг `project-init` выполнен.
