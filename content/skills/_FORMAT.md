# Формат навыка Googlagent

Навык — рабочая единица агента. Не значок и не промпт-заглушка. Навык лежит в каталоге
`content/skills/<ветка>/<slug>/` и состоит из двух файлов:

```
content/skills/<ветка>/<slug>/
  SKILL.md     инструкция: что делает, когда включается, как работает
  test.yaml    автотест: чем доказывается, что навык рабочий
```

Ветки (10, как в концепции): `strategy`, `research`, `sales`, `product`, `code`, `design`,
`content`, `video-voice`, `automation`, `personal`.

## Frontmatter SKILL.md (все поля обязательны)

| Поле | Что значит |
|---|---|
| `name` | slug навыка, `a-z0-9-` |
| `title` | название для человека |
| `branch` | одна из 10 веток |
| `version` | `v1`, `v2`, `v3` (кузница навыков) |
| `kind` | `build` — собирает продукт (код, сайт); `deliver` — готовит услугу или материалы; `method` — метод проведения (интервью, валидация) |
| `runs_via` | `dev-skills` (полный конвейер) или `direct` (одна фаза, без конвейера) |
| `min_level` | уровень агента 1–6, с которого доступна дорога «делает агент», если ей нужны возможности платформы (BUILDER, видео, расписания). Дорога «пройти самому» и методика доступны с уровня 1 |
| `triggers` | фразы и ситуации, когда агент предлагает навык |
| `inputs` | что нужно от человека и паспорта |
| `outputs` | что получает человек на выходе |
| `box_tiers` | `[economy, standard, premium]`, какие роли моделей на каждом уровне |
| `autotest` | путь к `test.yaml` |
| `source` | откуда навык: `studio`, `lesson-01`, `lesson-02`, `client`, `market` |

## Обязательные разделы тела

1. `## Назначение` — одна задача, один результат.
2. `## Когда включать` — триггеры и когда не включать.
3. `## Адаптация под паспорт` — переменные паспорта и как они меняют навык.
4. `## Допрос` — вопросы пачками не больше пяти, у каждого рекомендация (правила `grill-me`).
5. `## Конвейер` — фазы 0–6 из `_PIPELINE.md`, у каждой фазы то, что специфично для навыка.
6. `## Коробка ИИ` — три уровня (эконом, стандарт, премиум) в ролях моделей, не в ID.
7. `## Критерии приёмки` — нумерованные `К1…Кn`, наблюдаемые.
8. `## Отказы и границы` — что агент не делает, где останавливается и спрашивает.
9. `## Доказательство «Сработало»` — что именно приносит человек, чтобы навык засчитался.

## Правила

- **Факты о мире** (цены, законы, правила экзаменов, версии) в навык не вписываются: навык
  требует `run_research` со ссылкой и датой. Любая цифра в тексте навыка — только пример
  структуры и помечена `(пример)`.
- **Цены моделей** берутся из `model_catalog`. В навыке названы роли: `reasoning`, `fast`,
  `vision`, `image`, `video`, `tts`, `asr`, `code`.
- **Версии.** Правка навыка = новая версия. Старая остаётся у тех, кто на ней работает.
- **Адаптация.** `forge_skill` переписывает только раздел «Адаптация под паспорт» и
  подставляет значения в «Допрос» и «Конвейер». Критерии приёмки и автотест он не ослабляет.
- **Зачёт в счётчик** (решение Арсена): автотест пройден + результат на реальной задаче
  человека + кнопка «Сработало». До этого навык в дереве со статусом `не проверен`.

## Формат test.yaml

```yaml
skill: <slug>
version: v1
static:            # проверки текста навыка, выполняет tools/validate_skills.py
  required_sections: [...]
  min_criteria: 5
scenarios:         # прогон агента на тестовых вводных, оценка по чеклисту (как T12)
  - id: s1
    input: "..."
    must:          # без этого сценарий не засчитан
      - "..."
    must_not:
      - "..."
pass_score: 8      # из 10, на каждый сценарий
real_run_proof:    # что принимает кнопка «Сработало»
  - "..."
```

`static` проверяется валидатором без модели. `scenarios` прогоняются на тестовом боте
моделью-судьёй по чек-листу `must` и `must_not`. `real_run_proof` проверяет агент при
закрытии навыка у человека.
